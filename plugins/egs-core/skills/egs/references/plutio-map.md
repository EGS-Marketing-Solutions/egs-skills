# How our Plutio is organised

- **EGS TEAM WORK BOARD** is the one project most daily work lives in. Inside it, task boards
  such as Team Workspace, SEO Task Board and Website Projects, and within those, task groups:
  one per person (for example a manager's own group) and one per client execution plan (for
  example "Rural Authentic Wellness DPC 90-day execution plan > Month 3 Week 4").
- **One project per client** also exists, used for client-facing tasks and files.
- A task's breadcrumb (project > task board > task group) tells you which client and which phase
  it belongs to. Read it before you attribute a task to a client.
- Task link format: `https://clientportal.egs-solutions.com/projects/<project id>/tasks/<task id>`.
  Always link the task when you mention it.
- Statuses are coarse (incomplete, overdue, complete). The stage of the work is carried by the
  comment at each stage, which is why the stage-comment standard exists.

## The stage comments

Post one of these on the task when the work reaches that point. Plain words, one line, with a
link if there is one:

- Ready for client review: "Draft ready for review: <link>."
- Sent to client: "Sent to <name> by email on <date>, text sent through Amplify."
- Client approved: "<Name> approved on <date> (<where they said so>)."
- Published or sent: "Live at <link>" or "Sent on <date>."
- Closed: "Closing. <one line on the outcome>."

## What a good task looks like

Title: a verb and an object, with the client name. "Write the November newsletter for Friends
of ASH", not "Newsletter".

Description:
- Goal: what will be true when this is done.
- Situation: the client, why now, what happened before.
- Decided: names, dates, wording, links, in a list.
- Not decided: and who decides.
- Where things are: Drive folder, Chat space, previous task, recording.
- How it will be checked: what the reviewer looks at.

Owner: one person. Add others as followers or mention them, do not assign five people.
