# How we work fast with Claude

Ten habits. Each one exists because skipping it cost someone time.

## 1. Start with the sweep, not with your inbox

Your inbox shows what arrived. The sweep shows what is waiting on you across every channel, oldest
first, with the drafts already written. Open Claude before you open Gmail.

## 2. Let Claude write the first version

Your time goes to judging and deciding, not typing. If a task ends in something written (a reply,
copy, a report, a task description), Claude drafts it first and you edit. A blank page is the
slowest way to start anything.

## 3. Read the thread, not the badge

Unread, starred and "overdue" are markers nobody clears. The last message in a thread tells you
the real state. Teach yourself to look there, and Claude already does.

## 4. Give context, not instructions

When you hand work to a person or to Claude, say what it is for, what is already decided, where
the files are and how you will check it. The person works out the how, and catches a wrong step
on their own. A list of clicks gets followed exactly, including the wrong click.

## 5. One owner per task

Five assignees means everyone assumes someone else is watching. Assign one person; @mention
anyone you need something from.

## 6. Close the loop where the team can see it

A stage comment on the Plutio task at every step: ready for review, sent, approved, published,
closed. Thirty seconds each. It is the difference between a board people trust and one they
ignore.

## 7. Check before you report

Before you tell anyone where something stands, look at the live source. Yesterday's note is not
evidence. "I think it went out" becomes "it went out on 6 November" or "I have not verified it".

## 8. One job, one task

The same request arrives by email, in Chat and in a meeting. Find the existing task and comment on
it. Duplicates make the board unreadable.

## 9. Correct Claude in plain words, once

"Do not list tasks nobody has touched for a year." "Michaela handles Friends of ASH." Say it once.
If it is about you, Claude saves it for you. If it is about how the whole team works, Claude drafts
a change to the shared rules for Kyle to approve, and every Claude on the team learns it.

## 10. Turn repeat work into an SOP

When you finish something the team will do again, ask Claude for the SOP draft in the same
session, while every step is fresh. Two minutes now saves an hour of explaining later.

## A day, done this way

- First message to Claude: the sweep runs. Five client replies, a weekly update and a blog draft
  are waiting in `drafts/` when you start reading.
- You fix two sentences in one reply, approve the others, and send them yourself.
- You post the stage comments Claude wrote for you.
- A client sends new information in Chat. Claude folds it into the draft and writes the Plutio comment for you to post.
- At the end of a new process, you ask for the SOP. Claude writes it from what you just did.
